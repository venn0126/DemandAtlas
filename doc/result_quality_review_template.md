## 2. 文档目标

本文档用于统一评审 **需见** 输出结果的质量，重点判断：

1. 榜单是否可信
2. 需求聚类是否合理
3. 摘要是否被证据支撑
4. 增长榜是否被小样本污染
5. 机会榜是否过度主观

本文档的目标不是要求结果“完美”，而是让团队能系统回答：

> 当前结果是否已经足够可用，哪些问题必须修，哪些问题可以接受。

---

## 3. 使用方式

建议每次评审以一个 **QueryTask / ResultSnapshot** 为单位进行。

### 3.1 评审输入

每次评审至少记录：

- `query_task_id`
- `result_snapshot_id`
- 查询类型（one_click / directed）
- 主题模板或关键词
- 时间范围
- 视角（active / new）
- 评审人
- 评审日期

### 3.2 评审输出

每次评审结束后应输出：

1. 总体结论
2. 关键问题清单
3. 优先级建议
4. 是否允许继续灰度 / 上线

### 3.3 推荐评审频率

#### Sprint 内评审

- 每个新模板至少评审 1 次
- 每个主要排序改动后评审 1 次

#### 灰度阶段评审

- 每日抽样 3–5 个真实查询

---

## 4. 评审角色建议

建议至少由以下 2–3 类角色参与：

### A. 产品

关注：

- 结果是否符合产品定位
- 榜单是否“像需求”，而不是“像热帖”

### B. 数据 / 算法

关注：

- 聚类合理性
- 排序合理性
- 规则与边界处理

### C. 内容 / 运营 / 研究

关注：

- 需求是否有真实用户表达支撑
- 是否对内容选题 / 产品方向有用

---

## 5. 评审结论等级

建议使用 4 级结论：

### A. 可上线

- 结果整体可信
- 存在小问题，但不阻断使用

### B. 可灰度，需观察

- 结果基本可用
- 仍有明显问题，需要灰度期观察

### C. 暂不建议扩大使用

- 结果存在中等以上质量问题
- 仍可内部验证，但不建议扩大曝光

### D. 需要回退或重做

- 结果失真明显
- 榜单核心逻辑不可用

## 6. 核心评审维度

建议按 6 大维度评审。

## 6.1 需求识别准确度

问题：

- 这是不是一个真实需求，而不是噪声、梗图或泛讨论？

评审点：

- 是否能看出明确问题表达
- 是否有清晰场景
- 是否有反复出现的抱怨或需求陈述

评分建议：

- 5 = 明显是真需求
- 3 = 有需求特征但不够稳定
- 1 = 更像噪声或误判

## 6.2 聚类合理性

问题：

- 同一需求是否被合理归并？
- 是否存在“把多个问题混成一个”或“把一个问题拆成多个”？

评审点：

- 标题是否准确
- 摘要是否聚焦
- 证据是否围绕同一问题

评分建议：

- 5 = 聚类清晰
- 3 = 有轻微混杂
- 1 = 聚类明显错误

## 6.3 榜单排序合理性

问题：

- 排在前面的需求，是否真的比后面的更值得优先看？

评审点：

- 热门榜 Top 10 是否符合直觉
- 增长榜是否被小样本污染
- 机会榜是否被低置信度结果误占高位

评分建议：

- 5 = 排序基本合理
- 3 = 有个别异常项
- 1 = 排序整体不可信

## 6.4 证据支撑度

问题：

- 摘要和标签是否能被原话证据支持？

评审点：

- supporting evidence 是否真实支撑摘要
- opposing evidence 是否合理呈现
- 是否存在“摘要比证据更激进”的情况

评分建议：

- 5 = 证据与结论一致
- 3 = 基本一致但有过度概括
- 1 = 明显失真

## 6.5 可解释性

问题：

- 用户看到结果后，是否知道“为什么它排这里”？

评审点：

- 分数是否可理解
- 标签是否有帮助
- coverage / freshness / low confidence 提示是否足够

评分建议：

- 5 = 解释清晰
- 3 = 部分解释不充分
- 1 = 很难理解

## 6.6 实用性

问题：

- 这个结果对真实用户有没有决策价值？

评审点：

- 是否能转成内容选题
- 是否能转成产品机会判断
- 是否能帮助用户缩小判断范围

评分建议：

- 5 = 很有决策价值
- 3 = 有一定参考价值
- 1 = 参考价值弱

## 8. 详情页专项评审

## 8.1 标题与摘要

检查：

- 标题是否准确概括
- 摘要是否过度放大
- 标题与摘要是否对齐

## 8.2 scenes / pain_points / alternatives

检查：

- 是否从证据中抽出来
- 是否过于泛化
- 是否缺少核心信息

## 8.3 supporting / opposing evidence

检查：

- supporting evidence 是否真的支持结论
- opposing evidence 是否合理呈现反例或反对观点
- 是否存在 evidence 和标签相互矛盾

## 8.4 标签

检查：

- weak signal
- low confidence
- emerging signal

这些标签是否与内容相符。

## 9. 评分模板

建议每次评审对每个结果快照做一个总评分。

## 9.1 单次结果快照评分表

| 维度 | 分值范围 | 评分 |
|---|---:|---:|
| 需求识别准确度 | 1-5 |   |
| 聚类合理性 | 1-5 |   |
| 榜单排序合理性 | 1-5 |   |
| 证据支撑度 | 1-5 |   |
| 可解释性 | 1-5 |   |
| 实用性 | 1-5 |   |
| **总分** | **6-30** |   |

## 9.2 总分解释建议

- 26–30：质量较高，可灰度放量
- 21–25：基本可用，建议继续优化
- 16–20：问题明显，不建议扩大使用
- <=15：结果不可靠，建议回退或重构

## 10. 问题记录模板

建议每次评审记录问题清单。

## 10.1 问题清单表

| 问题 ID | 类型 | 严重级别 | 描述 | 示例 cluster / board | 建议动作 |
|---|---|---|---|---|---|
| RQ-001 | 排序 | 高 | 增长榜被小样本污染 | growth top 1 | 提高门槛 / 降级 emerging signal |
| RQ-002 | 聚类 | 中 | 两个不同需求被错误归并 | cluster detail | 调整 cluster merge 规则 |
| RQ-003 | 摘要 | 中 | 摘要比 evidence 更激进 | cluster detail | 收紧摘要生成规则 |

### 类型建议

- 排序
- 聚类
- 摘要
- 证据
- 标签
- UI 解释

### 严重级别建议

- 高：会误导用户决策，需优先修
- 中：影响质量，但不致命
- 低：体验优化项

## 12. 推荐抽样策略

## 12.1 模板抽样

每个重点模板至少抽样：

- 1 个 active 结果
- 1 个 new 结果

## 12.2 查询类型抽样

至少覆盖：

- one_click
- directed

## 12.3 边界场景抽样

建议额外抽样：

- no result
- partial_success
- weak signal
- low confidence
- emerging signal

---

## 13. 结果是否可上线的建议阈值

上线前建议至少满足：

- 热门榜平均评分 >= 4/5
- 增长榜平均评分 >= 3.5/5
- 证据支撑度平均评分 >= 4/5
- 高严重级别问题可控

### 风险接受条件

若机会榜仍偏粗糙，但：

- 热门榜稳定
- 增长榜稳定
- 详情 evidence 可信

则可以接受机会榜弱化上线。

## 15. 一句话结论

结果质量评审的关键，不是“大家觉得还行”，而是：

> **用同一套维度、分数和问题清单，持续判断需见的结果是否足够可信、可解释、可用。**
