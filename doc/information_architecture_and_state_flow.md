## 3. 设计原则

## 3.1 结果优先，不是搜索页优先

本产品的核心不是“让用户不断搜”，而是“让用户快速拿到可决策结果”。

因此页面结构应围绕：

- 查询发起
- 任务状态
- 榜单结果
- 需求详情

展开，而不是围绕“复杂检索工具栏”展开。

## 3.2 异步任务友好

由于 V1 存在缓存命中、异步执行、部分成功等情况，页面必须天然支持：

- 查询中
- 查询完成
- 部分成功
- 无结果
- 失败重试

## 3.3 快照驱动

结果页和详情页应该尽量绑定 `result_snapshot_id`，避免页面状态飘移。

## 3.4 状态可解释

页面不能只显示结果，还要显示：

- 当前视角（active / new）
- 结果覆盖说明
- 数据新鲜度
- 低置信度 / 弱信号标记

## 3.5 V1 克制

V1 以个人使用闭环为主，不要求复杂协作。

## 4. 用户与访问模式

## 4.1 匿名用户

可执行：

- 浏览首页
- 查看主题模板
- 发起基础查询
- 查看自己本次查询结果

不可执行：

- 保存查询
- 收藏需求
- 订阅提醒
- 导出到第三方

### 匿名模式设计要求

- 发起查询后需拿到临时访问权限
- 页面刷新后应尽量保留本次任务上下文
- 匿名模式下不应暴露“长期保存”型操作为主路径

## 4.2 登录用户

可执行：

- 匿名用户全部能力
- 后续收藏 / 保存 / 订阅 / 导出扩展能力

### V1 设计要求

- 即使登录态能力未全部上线，界面也要留好扩展位
- 但不要在 V1 把“未开放能力”放到主操作路径里

V1 建议一级页面如下：

1. 首页
2. 一键发现页
3. 定向发现页
4. 查询任务页
5. 结果页
6. 需求详情页

## 6. 核心页面定义

## 6.1 首页

### 页面目标

帮助用户理解产品价值，并快速进入两类查询模式。

### 核心模块

1. 顶部价值主张
2. 模式选择入口
   - 一键发现
   - 定向发现
3. 热门主题模板推荐
4. 产品说明
5. 示例结果预览

### 主操作

- 进入一键发现
- 进入定向发现

### 次操作

- 浏览模板详情
- 登录

### 状态要求

- 正常展示态
- 模板加载失败态

---

## 6.2 一键发现页

### 页面目标

让用户通过主题模板，低成本发起一次需求发现任务。

### 核心模块

1. 模板选择区
2. 时间范围选择区
3. 视角选择区
   - 活跃需求
   - 新发需求
4. 查询说明区
5. 执行按钮区

### 输入项

- 主题模板
- 时间范围
- view_type

### 主操作

- 立即发现

### 次操作

- 查看模板说明
- 切换时间范围
- 切换视角

### 页面状态

- 初始空白态
- 模板加载中
- 模板加载失败
- 参数可提交态
- 提交中

### 成功后跳转

- 缓存命中：直接进入结果页
- 未命中缓存：进入查询任务页

---

## 6.3 定向发现页

### 页面目标

让用户围绕明确关键词或社区，发起定向验证任务。

### 核心模块

1. 关键词输入区
2. 社区范围区
3. 语言区
4. 地域线索区
5. 时间范围区
6. 互动门槛区
7. 视角选择区
8. 输入建议区

### 输入项

- keywords
- subreddits
- language
- region_hints
- time_window
- min_engagement_threshold
- view_type

### 主操作

- 开始分析

### 次操作

- 使用示例关键词
- 清空条件

### 页面状态

- 初始空白态
- 正常编辑态
- 输入过泛警告态
- 输入歧义警告态
- 超限态
- 提交中

### 成功后跳转

- 缓存命中：直接进入结果页
- 未命中缓存：进入查询任务页

---

## 6.4 查询任务页

### 页面目标

承接异步任务执行状态，让用户知道系统正在做什么，以及何时可以看到结果。

### 核心模块

1. 任务状态头部
2. 当前阶段展示区
3. 进度条
4. 查询条件摘要
5. 覆盖说明区（如有）
6. 自动刷新与手动刷新区
7. 错误提示区

### 页面状态

#### A. pending

- 显示“任务已创建，等待执行”

#### B. running

- 显示当前 stage
- 显示进度

#### C. partial_success

- 显示“已生成部分结果”
- 引导进入结果页

#### D. success

- 自动跳转或引导进入结果页

#### E. failed

- 显示失败原因
- 提供重试 / 返回修改查询

### 主操作

- 查看结果
- 刷新状态
- 返回修改查询

### 次操作

- 停留等待
- 复制任务链接（登录后或匿名受控）

---

## 6.5 结果页

### 页面目标

以榜单形式展示一次 QueryTask 的主要需求发现结果。

### 核心模块

1. 查询摘要头部
2. 视角与榜单切换条
3. 数据覆盖与新鲜度提示条
4. 榜单列表区
5. 空状态 / 弱信号状态区
6. 分页 / 查看更多区
7. 导出入口区

### 查询摘要头部应显示

- 当前查询模式
- 时间窗口
- 模板或关键词
- 当前视角
- 生成时间

### 榜单切换

- 热门需求榜
- 高增长需求榜
- 高机会需求榜

### 榜单条目应显示

- 排名
- 标题
- 摘要
- 关键分数
- 样本量
- 社区分布
- 标签：
  - 低置信度
  - 样本不足
  - 新兴信号

### 页面状态

#### A. 正常结果态

- 榜单可用

#### B. 无结果态

- 没有形成有效需求
- 提示调整关键词 / 时间 / 社区范围

#### C. 样本不足态

- 有结果但不够稳定
- 结果可看但需提示谨慎解读

#### D. 低置信度态

- 聚类可信度较低
- 降低过强行动引导

#### E. 部分成功态

- 展示 coverage note
- 显示结果可用但不完整

### 主操作

- 切换榜单
- 查看需求详情
- 导出结果

### 次操作

- 切换 active / new
- 重新运行查询

---

## 6.6 需求详情页

### 页面目标

围绕单个 `cluster_id` 展示完整需求卡片与证据。

### 核心模块

1. 详情头部
2. 分数与标签区
3. 场景 / 痛点 / 替代方案区
4. 支持观点区
5. 反对观点区
6. 社区分布区
7. 时间趋势区
8. 证据列表区
9. 导出 / 后续动作区

### 详情头部应显示

- 需求标题
- 一句话摘要
- 时间窗口
- 当前榜单来源

### 分数与标签区应显示

- discussion_score
- attention_score
- growth_score
- opportunity_score
- confidence_score
- is_weak_signal
- is_low_confidence
- is_emerging_signal

### 页面状态

#### A. 正常详情态

- 字段完整
- 证据可读

#### B. 原文部分不可访问态

- 某些证据只有最小引用信息

#### C. 低置信度态

- 分析结论需弱化表达

#### D. 观点冲突态

- 同一需求同时有支持和反对证据

### 主操作

- 返回结果页
- 导出本需求

### 次操作

- 登录后收藏（V1 可先隐藏或灰置）

## 7. 关键用户任务流

## 7.1 流程 A：一键发现，命中缓存

```text
首页
  -> 一键发现页
  -> 选择模板 + 时间范围 + 视角
  -> 提交查询
  -> 命中缓存
  -> 直接进入结果页
  -> 点击需求详情
```

### 设计重点

- 用户应感知为“很快得到结果”
- 不需要经过查询任务页

## 7.2 流程 B：一键发现，进入异步任务

```text
首页
  -> 一键发现页
  -> 提交查询
  -> 未命中缓存
  -> 查询任务页
  -> running
  -> success
  -> 进入结果页
```

### 设计重点

- 查询任务页要清晰解释“系统正在做什么”
- 不要让用户觉得页面卡住

## 7.3 流程 C：定向发现，结果部分成功

```text
首页
  -> 定向发现页
  -> 输入关键词与条件
  -> 提交查询
  -> 查询任务页
  -> partial_success
  -> 进入结果页
  -> 顶部显示 coverage note
```

### 设计重点

- partial_success 不是失败
- 需要展示结果可用但不完整

## 7.4 流程 D：查询失败后修改条件重试

```text
定向发现页
  -> 提交查询
  -> 查询任务页
  -> failed
  -> 返回定向发现页
  -> 调整关键词或时间范围
  -> 再次提交
```

### 设计重点

- 错误消息要能指导用户改什么

## 7.5 流程 E：从结果页切换视角

```text
结果页(active)
  -> 切换到 new
  -> 发起或命中新 QueryTask / Snapshot
  -> 进入 new 视角结果页
```

### 设计重点

- active/new 不是前端本地过滤
- 本质上是另一份结果

## 8. 前后端状态映射

## 8.1 QueryTask 状态映射

| 后端状态 | 前端页面 | 展示策略 |
|---|---|---|
| pending | 查询任务页 | 等待执行提示 |
| running | 查询任务页 | 进度与阶段展示 |
| partial_success | 查询任务页 / 结果页 | 提示部分成功并允许进入结果 |
| success | 结果页 | 正常结果展示 |
| failed | 查询任务页 | 错误说明与重试引导 |

## 8.2 ResultSnapshot 状态映射

虽然 ResultSnapshot 本身不一定有独立状态字段，但前端需从数据推导：

| 条件 | 页面状态 |
|---|---|
| cluster_count = 0 | 无结果 |
| cluster_count > 0 且样本低 | 样本不足 |
| 多个 cluster low_confidence | 低置信度 |
| coverage_note 非空且关键字段存在 | 部分成功 |
| 正常 | 正常结果 |

## 8.3 Cluster 级状态映射

| 字段 | 前端标签 |
|---|---|
| is_weak_signal = true | 弱信号 |
| is_low_confidence = true | 低置信度 |
| is_emerging_signal = true | 新兴信号 |

## 9. 页面状态矩阵

## 9.1 一键发现页状态矩阵

| 状态 | 触发条件 | UI 表现 |
|---|---|---|
| 模板加载中 | 首次进入 | skeleton / loading |
| 模板加载失败 | API 错误 | 重试提示 |

| 提交中 | 点击提交 | 按钮 loading |
| 输入不完整 | 未选模板 | 禁用提交按钮 |

## 9.2 定向发现页状态矩阵

| 状态 | 触发条件 | UI 表现 |
|---|---|---|
| 初始空白 | 初次进入 | 空白引导 |
| 输入中 | 编辑中 | 正常表单 |
| 过泛警告 | query 校验返回 warning | 黄色提示 |
| 歧义警告 | query 校验返回 warning | 黄色提示 |
| 超限错误 | 参数超限 | 红色错误提示 |
| 提交中 | 点击提交 | 按钮 loading |

## 9.3 查询任务页状态矩阵

| 状态 | 触发条件 | UI 表现 |
|---|---|---|
| pending | status=pending | 等待执行 |
| running | status=running | 阶段与进度 |
| partial_success | status=partial_success | 可进入结果 + coverage note |
| success | status=success | 自动跳转或 CTA |
| failed | status=failed | 错误 + 重试 |

## 9.4 结果页状态矩阵

| 状态 | 触发条件 | UI 表现 |
|---|---|---|
| 正常结果 | 有榜单结果 | 标准列表 |
| 无结果 | cluster_count=0 | 空状态 + 调整建议 |
| 样本不足 | 结果不为空但证据不足 | 样本不足提示 |
| 低置信度 | 多条结果低置信度 | 全局说明条 |
| 部分成功 | coverage_note 非空 | 顶部说明条 |

## 9.5 详情页状态矩阵

| 状态 | 触发条件 | UI 表现 |
|---|---|---|
| 正常详情 | 字段完整 | 标准详情 |
| 原文不可访问 | availability 非 public | 降级展示 |
| 低置信度 | cluster flag | 风险提示 |
| 观点冲突 | supporting + opposing 均存在 | 双栏目展示 |

## 10. 核心交互规则

## 10.1 提交查询后的跳转规则

### 命中缓存

- 不经过查询任务页
- 直接进入结果页

### 未命中缓存

- 进入查询任务页

### 设计建议

- 前端无需让用户显式选择“同步 / 异步”
- 由后端决定，前端只根据返回结果路由

## 10.2 active / new 切换规则

- 切换视角时应视为新结果上下文
- 允许复用已存在快照
- 若无快照则创建新任务

## 10.3 榜单切换规则

- hot / growth / opportunity 切换应尽量在同一 `result_snapshot_id` 内完成
- 不应因为切榜而新建任务

## 10.4 查看详情规则

- 详情页必须绑定：
  - `result_snapshot_id`
  - `cluster_id`

这样才能保证：

- 与当前榜单上下文一致
- 导出与回溯一致

## 10.5 刷新规则

### 查询任务页刷新

- 可轮询
- 可手动刷新

### 结果页刷新

- 默认刷新页面只重新获取该 `result_snapshot_id`
- 不应隐式重跑查询

### 强制刷新查询

- 应通过显式按钮触发新 QueryTask

## 13. 空状态与错误状态文案方向

## 13.1 无结果态

目标：

- 不让用户误以为系统坏了

文案方向：

- 当前条件下没有足够讨论形成有效需求
- 可尝试放宽时间范围、扩大社区范围或调整关键词

## 13.2 样本不足态

目标：

- 告诉用户“有信号，但还不稳”

文案方向：

- 当前结果可作为弱信号参考
- 建议扩大时间范围或增加候选社区

## 13.3 低置信度态

目标：

- 降低用户对 AI 归纳结果的过度信任

文案方向：

- 当前需求聚类可信度较低
- 建议结合原始证据进一步判断

## 13.4 部分成功态

目标：

- 让用户知道结果能用，但覆盖不完整

文案方向：

- 已生成可用结果，但部分数据源不可用
- 当前结果可能低估部分需求热度

## 13.5 失败态

目标：

- 引导用户下一步动作

文案方向：

- 当前查询未能生成可用结果
- 请缩小范围、调整关键词或稍后重试

## 15. 前端状态管理建议

## 15.1 状态分层

建议前端将状态拆为：

### A. 输入状态

- 当前查询条件
- 表单校验

### B. 任务状态

- query_task_id
- status
- current_stage
- progress

### C. 结果状态

- result_snapshot_id
- board_type
- page_token

### D. UI 标签状态

- is_weak_signal
- is_low_confidence
- is_emerging_signal
- coverage_note

## 15.2 不建议的做法

不建议：

- 让榜单页自己推断任务状态
- 让详情页脱离 `result_snapshot_id` 单独请求“最新结果”

## 18. 一句话结论

本产品的页面设计核心，不是做一个“复杂搜索台”，而是：

> **围绕 QueryTask 和 ResultSnapshot，把一次需求发现过程拆成用户可理解、前端可管理、后端可映射的状态化体验。**
