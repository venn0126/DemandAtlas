## 2. 风格定稿结论

本产品 V1 的界面风格正式定为：

> **Research Console / 冷静型研究工作台**

它不是：

- 社媒信息流产品
- 炫技型 AI 产品
- 数据大屏产品
- 重营销落地页产品

它应该是：

- 面向研究与判断的 B2B 工具
- 面向异步任务结果消费的分析台
- 面向证据回溯的结构化工作界面

---

## 3. 风格定位

## 3.1 风格关键词

- 冷静
- 专业
- 可信
- 低噪
- 高信息密度
- 强层级
- 可追溯

## 3.2 产品气质

用户打开这个产品，应该感受到：

1. 这是一个认真做分析的工具
2. 这是一个可以长期使用的工作台
3. 结果是有依据、有结构、有边界的

而不应该感受到：

1. 这是个热闹的内容社区
2. 这是个炫目的 AI 演示产品
3. 这是个“只会堆图表”的看板工具

---

## 4. 视觉参考方向

本产品推荐采用以下混合风格：

### 4.1 结构参考

- **Perplexity 风格**
  - 查询入口清晰
  - 结果结构自然
  - 强“搜索 -> 结果 -> 下钻”的工作流

### 4.2 模块化参考

- **Semrush 风格**
  - 分析模块清晰
  - 信息块有层次
  - 仪表型内容与结果型内容兼容

### 4.3 质感参考

- **Linear 风格**
  - 低噪音
  - 节制的高对比
  - 干净、专业、现代

### 4.4 信息组织参考

- **Notion 风格**
  - 信息块自然堆叠
  - 文本与结构信息共存
  - 不强调装饰，强调内容承载

## 4.5 最终风格组合

建议定为：

> **Perplexity 的查询结构 + Semrush 的分析模块 + Linear 的低噪质感**

## 5. 总体视觉策略

## 5.1 主界面模式

V1 默认采用：

- **浅色主题为主**
- 暗色主题可作为后续扩展

### 原因

- 榜单、卡片、证据、分数、说明在浅色环境下更易读
- 更适合长时间分析
- 更容易建立“研究工具”心智

## 5.2 视觉重点

视觉优先级应为：

1. 查询上下文
2. 结果是否可靠
3. 榜单条目结构
4. 证据与解释

不应优先强化：

- 插画
- 背景纹理
- 炫光装饰
- 情绪化渐变

## 6. 配色系统定稿

## 6.1 基础中性色

### 页面背景

- `bg.canvas = #F7F8FA`
- `bg.surface = #FFFFFF`
- `bg.subtle = #F3F4F6`

### 边框

- `border.default = #E5E7EB`
- `border.strong = #D1D5DB`

### 文本

- `text.primary = #111827`
- `text.secondary = #6B7280`
- `text.tertiary = #9CA3AF`

## 6.2 主强调色

建议主色采用冷静蓝：

- `brand.primary = #4F7CFF`
- `brand.primary.hover = #3F6EF5`
- `brand.primary.soft = #EEF3FF`

### 说明

- 这个蓝色足够现代，但不浮躁
- 适合做主 CTA、tab 激活、focus 态

- `success.bg = #ECFDF3`
- `success.border = #BBF7D0`

- `warning.border = #FCD34D`

- `danger.border = #FECACA`

### 信息提示

## 7. 字体与排版系统

## 7.1 字体策略

推荐：

- 中文：系统无衬线优先
- 英文 / 数字：系统无衬线优先

### 建议字体栈

```text
Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif
```

中文可由系统字体兜底：

```text
"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif
```

## 7.2 字重建议

- 标题：600
- 模块标题：600
- 正文：400
- 强调正文 / 标签：500
- 数字指标：600

## 7.3 字号层级

### 页面级

- `display = 32`
- `page_title = 24`
- `section_title = 18`

### 内容级

- `body_lg = 16`
- `body_md = 14`
- `body_sm = 13`
- `caption = 12`

### 数据级

- `metric_lg = 24`
- `metric_md = 18`
- `metric_sm = 14`

## 7.4 行高建议

- 32 对应行高 40
- 24 对应行高 32
- 18 对应行高 28
- 16 对应行高 24
- 14 对应行高 22
- 12 对应行高 18

## 8. 间距与栅格

## 8.1 间距系统

采用 4px 基准。

### 建议 token

- `space-1 = 4`
- `space-2 = 8`
- `space-3 = 12`
- `space-4 = 16`
- `space-5 = 20`
- `space-6 = 24`
- `space-8 = 32`
- `space-10 = 40`
- `space-12 = 48`

## 8.2 页面宽度建议

### 内容页

- 最大内容宽度：`1280px`

### 表单页

- 中心内容宽度：`720px`

### 结果页

- 推荐 `1200px - 1280px`

## 8.3 栅格建议

### 结果页

建议采用：

- 12 栏栅格

### 详情页

建议采用：

- 主信息 8 栏
- 辅助信息 4 栏

## 9. 形状与层次

## 9.1 圆角

建议统一使用中等圆角：

- `radius.sm = 8`
- `radius.md = 10`
- `radius.lg = 12`
- `radius.xl = 16`

### 推荐用法

- 输入框：10
- 卡片：12
- badge：9999（胶囊）

## 9.2 阴影

V1 推荐：

- **弱阴影 + 清晰边框**

不要用重投影。

### 建议 token

- `shadow.sm = 0 1px 2px rgba(16,24,40,0.05)`
- `shadow.md = 0 4px 12px rgba(16,24,40,0.06)`

### 原则

- 列表卡片主要靠边框分层
- 悬浮态再轻微加阴影

## 9.3 分割线

建议大量使用细边框与弱背景区分层次，而不是使用厚色块。

## 10. 组件风格定稿

## 10.1 按钮

### 主按钮

- 背景：`brand.primary`
- 文字：白色
- 圆角：10
- 高度：40 / 44

### 次按钮

- 白底
- 1px 边框
- hover 使用浅灰背景

### 危险按钮

- 仅在明确 destructive 行为时使用

## 10.2 输入框

### 风格原则

- 白底
- 1px 中性边框
- focus 时使用蓝色边框 + 轻微外发光

### 不推荐

- 厚描边
- 过深阴影
- 高饱和背景色

## 10.3 卡片

卡片是本产品最核心的载体。

### 卡片样式建议

- 白色背景
- 1px 边框
- 圆角 12
- 内边距 16–20
- hover 时边框加深或轻阴影

### 卡片内部层级

- 标题
- 摘要
- 标签 / 分数
- 次级元信息
- 操作入口

## 10.4 Tabs

用于：

- 热门 / 增长 / 机会
- 可选 active / new 视图切换

### 样式建议

- 底部细指示线
- 或浅底 pill，但不要过于“社交 app”

### 推荐

- `board tabs` 用底部线型
- `view type toggle` 用 segmented control

## 10.5 Badge / Tag

这是高频组件，必须系统化。

### 类型

- 状态类 badge
- 信号类 badge
- 分数类 badge
- 社区类 tag

### 风格

- 小尺寸
- 细边框
- 低饱和底色
- 中高对比文字

## 10.6 Banner

用于展示：

- coverage note
- 数据新鲜度
- partial_success
- 样本不足
- 低置信度

### 风格

- 浅底色
- 左侧小图标
- 单行摘要 + 可选展开

### 重点

Banner 要像“系统说明”，不要像“营销提示”。

## 11. 图表与数据可视化

## 11.1 V1 原则

V1 不做重图表产品。

图表只用于：

- 趋势辅助
- 指标补充

而不是主要内容。

## 11.2 推荐图表类型

- 简单折线图：趋势
- 简单柱状图：社区分布
- 简单条形图：分数比较

## 11.3 不推荐

- 复杂雷达图
- 3D 图
- 多层饼图
- 过度渐变图表

## 11.4 图表风格

- 线条清晰
- 少网格线
- 色彩克制
- 标注优先

---

## 12. 页面级风格建议

## 12.1 首页

### 视觉目标

- 清晰表达产品价值
- 快速引导进入两种模式

### 风格建议

- 简洁 Hero
- 不要做重插画
- 模板推荐用卡片式

## 12.2 查询页

### 视觉目标

- 让用户快速理解表单
- 提交路径清晰

### 风格建议

- 中心化表单
- 模块块状清晰
- warning 不抢主视觉

## 12.3 查询任务页

### 视觉目标

- 消除等待焦虑
- 让用户知道系统正在工作

### 风格建议

- 阶段式进度展示
- 轻状态卡片
- 不要只放 spinner

## 12.4 结果页

### 视觉目标

- 快速判断
- 快速对比
- 快速下钻

### 风格建议

- 顶部摘要清晰
- tabs 清晰
- 列表高信息密度
- coverage / freshness 用系统 banner

## 12.5 详情页

### 视觉目标

- 让“需求为什么成立”一眼可解释

### 风格建议

- 标题与摘要优先
- 分数与标签并列展示
- supporting / opposing evidence 分栏
- 证据卡片简洁

---

## 13. 交互与动效建议

## 13.1 动效原则

- 轻
- 快
- 不干扰理解

## 13.2 推荐动效

- hover 阴影轻微变化
- tab 切换轻过渡
- loading skeleton
- 导出状态 badge 变化

## 13.3 不推荐

- 大面积视差
- 粒子背景
- 强弹性动画
- 夸张的卡片翻转

---

## 14. 可访问性建议

## 14.1 对比度

- 主文字与背景保证高对比
- tag 颜色不能只靠颜色区分语义

## 14.2 状态表达

以下状态必须同时使用：

- 颜色
- 图标
- 文案

不要只靠颜色区分：

- 成功
- 警告
- 失败
- 低置信度

## 14.3 键盘导航

至少保证：

- 表单可 tab 操作
- tabs 可键盘切换
- 导出与详情操作可访问

---

## 15. 明确不采用的风格

以下风格在 V1 明确排除：

## 15.1 赛博霓虹 AI 风

原因：

- 不利于可信分析
- 影响长时间阅读

## 15.2 数据大屏风

原因：

- 与任务型产品不匹配
- 不利于下钻和证据阅读

## 15.3 社交信息流风

原因：

- 会削弱“结果卡片”的工具属性

## 15.4 过强营销 Landing Page 风

原因：

- 会削弱产品本身的工作台属性

---

## 16. 设计实现建议

## 16.1 Token 优先

建议先定义：

- color tokens
- spacing tokens
- radius tokens
- typography tokens
- shadow tokens

## 16.2 组件优先级

建议先做以下基础组件：

1. Button
2. Input
3. Card
4. Badge
5. Banner
6. Tabs
7. EmptyState
8. ErrorState
9. LoadingState

## 16.3 先做页面顺序

建议按以下顺序出视觉稿：

1. 结果页
2. 详情页
3. 定向发现页
4. 一键发现页
5. 查询任务页
6. 首页

### 原因

结果页和详情页最能定义产品气质。

---

## 17. 一句话风格标准

最终视觉标准可归纳为：

> **像一个可信、冷静、低噪、以证据为核心的研究工作台，而不是一个花哨的 AI 展示产品。**
